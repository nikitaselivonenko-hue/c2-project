# C2 Project — учебная имитация инфраструктуры удалённого управления

Учебный проект, демонстрирующий архитектуру Command & Control (C2) с обфускацией трафика под протокол SMB. Проект создан исключительно в образовательных целях и не предназначен для использования в реальных сетях.

## Архитектура

Система состоит из трёх компонентов:

| Компонент | Роль | Протоколы |
|-----------|------|-----------|
| **Терминал оператора** (`cmd/terminal`) | Ввод команд оператором, отображение результатов | HTTP-клиент → C2 |
| **C2-сервер** (`cmd/c2server`) | Промежуточный узел, очередь задач, маршрутизация | HTTP-сервер ← терминал, TCP-сервер (псевдо-SMB) → клиент |
| **Клиент** (`cmd/client`) | Выполнение команд на целевой машине | TCP-клиент (псевдо-SMB) → C2 |

Схема взаимодействия:

```text
[Терминал] --HTTP--> [C2-сервер] --псевдо-SMB (TCP :445)--> [Клиент]
     ^                    |                                     |
     |                    |                                     |
     +----HTTP статус-----+<----псевдо-SMB (TCP :445)-----------+
```

## Обфускация трафика

Пакеты между C2-сервером и клиентом имеют структуру, идентичную заголовку SMB2 (64 байта), но передаются поверх обычного TCP-соединения на порт 445. Библиотеки SMB не используются — заголовок формируется вручную:

- **ProtocolId** — маркер `\xfeSMB` (4 байта)
- **StructureSize** — размер заголовка (2 байта)
- **Status** — статус операции (4 байта)
- **Command** — код команды C2 (2 байта): `Register`, `GetTask`, `TaskData`, `SendResult`, `RegisterAck`, `ResultAck`
- **MessageId**, **SessionId**, **TreeId** — идентификаторы
- **Signature** — 16 байт (заполнены нулями, так как шифрование обеспечивается на уровне полезной нагрузки)
- **Payload** — зашифрованные данные

> Поле `Reserved` SMB2-заголовка переиспользовано под длину payload. Это осознанное решение: стандартный TCP-поток не гарантирует, что пакет придёт одним сегментом, поэтому length-prefix нужен для корректной обработки длинных выводов команд.

## Шифрование

Используется симметричный алгоритм AES-256-GCM. Двухслойная схема:

- **Первый слой** (терминал ↔ C2): ключ `KeyTerminalToC2`
- **Второй слой** (C2 ↔ клиент): ключ `KeyC2ToClient`

Команда, введённая оператором, шифруется первым ключом на терминале, расшифровывается на C2, перешифровывается вторым ключом и передаётся клиенту. Результат выполнения проходит обратный путь. Ключи заданы в `internal/protocol/protocol.go` в учебных целях.

## Требования к среде

- Go 1.21 или новее
- Linux или Windows для запуска C2-сервера
- Windows 10/11 для запуска клиента (в текущей реализации используется `cmd.exe`)
- Свободный порт 445 (на Linux требует прав root)
- Свободный порт 8080

## Сборка

Все компоненты собираются из корня проекта. При кросс-компиляции удобно задать переменные окружения, чтобы не забивать системный диск.

Linux/macOS:

```bash
export GOCACHE=$HOME/.cache/go-build
export GOPATH=$HOME/go
```

Windows (cmd):

```cmd
set GOCACHE=G:\go-cache
set GOTMPDIR=G:\go-temp
set GOPATH=G:\go-path
```

Сборка C2-сервера под Linux:

```cmd
set GOOS=linux
set GOARCH=amd64
go build -o dist/c2server_linux ./cmd/c2server
```

Сборка клиента и терминала под Windows:

```cmd
set GOOS=windows
set GOARCH=amd64
go build -o dist/client_win.exe ./cmd/client
go build -o dist/terminal_win.exe ./cmd/terminal
```

## Тесты

```cmd
go test ./...
```

Покрытие unit-тестами:

- `internal/crypto` — шифрование/дешифрование, неверный ключ, повреждённый шифртекст
- `internal/packet` — сериализация/десериализация, чтение/запись по TCP, некорректные данные
- `internal/storage` — регистрация клиентов, очередь задач, установка результата
- `internal/service` — создание задач, хранение результатов, статусы

## Запуск

### 1. Запуск C2-сервера (Linux)

```bash
cd /home/user
sudo ./c2server_linux
```

Ожидаемый вывод:

```text
2026/... [C2] TCP-сервер запущен на :445
2026/... [C2] HTTP-сервер запущен на :8080
```

> Порт 445 требует прав root. Если хотите запускать без `sudo`, измените порт в `cmd/c2server/main.go`:

```go
tcpSrv := tcpserver.NewServer(":4445", tcpserver.NewClientHandler(svc))
```

и в клиенте (`internal/agent/agent.go`, `DefaultConfig`) укажите адрес с этим портом.

### 2. Запуск клиента (Windows)

```cmd
client_win.exe
```

Ожидаемый вывод:

```text
2026/... [CLIENT] подключение к C2 <IP>:445
2026/... [CLIENT] зарегистрирован на C2
```

> Клиент переподключается автоматически каждые 10 секунд при потере связи. Интервал опроса задач рандомизирован в диапазоне 2–5 секунд, чтобы избежать детектирования по фиксированному периоду.

### 3. Запуск терминала оператора

```cmd
terminal_win.exe
```

Ожидаемый интерфейс:

```text
=== C2 Terminal ===

Команды: /clients — выбрать клиента, /exit — выход
>
```

Последовательность работы:

1. Ввести `/clients` — список зарегистрированных клиентов.
2. Выбрать номер клиента.
3. Ввести команду (например, `ipconfig`, `whoami`, `dir C:\`).
4. Дождаться результата выполнения.

## Адреса компонентов

По умолчанию используются следующие адреса:

- **C2-сервер**: `192.168.56.104` (HTTP `:8080`, TCP `:445`)
- **Клиент**: адрес C2 зашит в `internal/agent/agent.go` (`DefaultConfig`)
- **Терминал оператора**: `internal/operator/client.go` → константа `c2URL` в `cmd/terminal/main.go`

Если ваши адреса отличаются, измените их в:

- `cmd/terminal/main.go` — константа `c2URL`
- `internal/agent/agent.go` — поле `C2Address` в `DefaultConfig()`

## Возможности

- Регистрация клиента с уникальным идентификатором (hostname + OS + username)
- Очередь задач на C2-сервере (в памяти процесса)
- Асинхронное выполнение команд: терминал отправляет задачу и опрашивает статус
- Захват STDOUT и STDERR при выполнении команд
- Двухслойное шифрование AES-256-GCM
- Обфускация под SMB2
- Автоматическое переподключение клиента с рандомизацией интервала опроса
- Read deadline 60 секунд на TCP-соединениях (защита от зависших клиентов)
- `recover()` в горутинах TCP-соединений (паника одной горутины не роняет сервер)
- Graceful shutdown по SIGINT/SIGTERM через `errgroup` и `context`
- Поддержка UTF-8 в терминале (корректное отображение русского текста)

## Ограничения учебной реализации

- Ключи шифрования зашиты в исходный код (в реальных системах требуется обмен ключами)
- Хранилище задач находится в оперативной памяти и очищается при перезапуске C2
- Порт 445 требует прав root на Linux
- Клиент не имеет механизмов устойчивости (persistence) — запускается вручную
- Отсутствует аутентификация оператора на C2 (любой, кто знает адрес, может отправить задачу)
- Сжатие payload (Deflate) не реализовано, помечено в задании как опциональное
